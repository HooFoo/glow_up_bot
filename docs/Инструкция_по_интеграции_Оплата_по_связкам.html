Интеграция по токену (оплата по связкам)

Возможность безакцептного списания суммы с карты плательщика



1 этап

Перед началом интеграции Вам необходимо придумать параметр sys, который будет являться кодом Вашей системы. (слово на английской раскладке, маленькими буквами. Обычно разработчики закладывают сюда название своей системы)

Этот параметр нужно сообщить сотрудникам поддержки Продамус, для фиксации в системе (по нему система будет выдавать соответствующие разрешения)

После того, как параметр будет зарегистрирован, поддержка Продамуса Вам выдаст ключ,

с помощью которого можно будет продолжить дальнейшую интеграцию

2 этап

При использовании этого варианта настройки интеграции Ваша система может получать в веб-хуках от Продамуса специальный токен и проводить оплату с его помощью через api

Для того, чтобы получить данный токен, при формировании платежной ссылки, необходимо сформировать запрос на оплату, включив параметр

client_id, значением которого должен быть уникальный идентификатор пользователя на стороне Вашей системы. Тип значения - строка длиной до 32 символов.

После оплаты пользователем, на указанный url-адрес будет отправлен веб-хук, содержащий токен.

P.S. Если вы передали при запросе client_id будет доступен способ оплаты, только картой. Чтобы были доступны и остальные способы нужно передать return_all_methods со значением 1

Для оплаты по токену необходимо сделать запрос к api платежной формы по адресу в формате:

https:// домен вашей платежной страницы /rest/payment/do/

Например: https://producer.payform.ru/rest/payment/do

У каждого клиента домен платежной страницы уникален. При тестировании следует использовать адрес тестовой страницы, который Вам выдаст поддержка Продамуса.

В качестве параметров принимаются те же данные, как при формировании платежной ссылки (за исключением do). В запросе необходимо передать обязательные параметры:

  1. binding_id - платежный токен полученный в хуке

  2. client_id – уникальный идентификатор пользователя на стороне Вашей системы, который должен совпадать со значением, переданным в ссылке при первой оплате

  3. sys - код системы

Запрос к api необходимо подписать секретным ключом, выданным поддержкой Продамуса

Внимание! Ключ подписи для оплаты по токену не совпадает с ключом, указанным в настройках конкретной платежной страницы ( выданной Вам на тестирование) и выдается поддержкой.

Так же обращаем внимание на то, что подпись необходимо передать в теле запроса в параметре signature (так же как при формировании платежной ссылки)

в случае успешной оплаты, api должен вернуть следующий ответ:

{"success":true}

в случае не успешной:

{"success":false,"error":"текст ошибки"}

так же при оплате через api будут отправлены те же уведомления, что и при обычной оплате (веб-хук, email). формат данных уведомлений пока отличаться не будет

Веб-хуки

В веб-хуки добавлен параметр payment_init, который может принимать три значения: manual, auto, api. при оплате по токену через апи payment_init будет принимать значение "api"
